# 공통 번호 체계와 문단 배치

이 문서는 **기본 보고서형 (`basic-report`) 전용**이다. 섹션 구분형은
[sectioned-layout.md](sectioned-layout.md)를 따르며 아래 번호·제목 후처리를 자동 적용하지 않는다.

## 적용 범위

새 공문·보고서·계획서는 `1. → 가. → 1) → 가) → (1) → (가) → ① → ㉮`를 기본으로 한다.
필요한 깊이까지만 사용한다. 같은 부모의 항목이 하나면 부호를 생략한다.
`※` 참고와 `*` 주석은 해당 문단에 부속되며 다음 하위 레벨로 세지 않는다.
기관 고정 서식과 사용자 지정 형식은 우선한다. 기존 문서의 내용 수정/포맷 변환에는
번호 정규화를 적용하지 않는다. 설문의 문항 ID·선택지 코드·본문 상호참조도 유지한다.

근거: [2025 행정업무운영 편람](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000012&nttId=122878)
(2026-01-02 게시), 본문 51~53쪽. 편람은 특수기호도 허용한다. 번호 체계를 보고서까지
공통으로 채택하는 것은 사용자 선택이다. 아래 배치 원칙/제안값은 법정 수치가 아니다.

## 입력과 생성

문서 제목만 `#`로 쓴다. 번호 붙일 본문은 2칸씩 중첩한 Markdown 순서 목록으로 작성한다.
각 항목의 `1.`은 구조 표시이므로 최종 `가.`, `1)` 등을 내용에 또 적지 않는다.
번호 붙일 장 제목을 `##`로 섞으면 별도 헤딩이 되어 번호가 연결되지 않으므로 피한다.
MD 들여쓰기 공백은 파서 입력용이며 출력에서 반복 공백으로 정렬하라는 뜻이 아니다.

```markdown
# 업무 개선 계획
1. 추진 배경
  1. 현황
  1. 개선 필요성
1. 추진 내용
  1. 준비
  1. 실행
```

`python3 <public-report-style>/scripts/generate_numbered.py draft.md --out new.hwpx --preset report`

helper는 설치된 kordoc 공개 `markdownToHwpx` API를 사용한다. report/plan 외형에
`numbering: standard`를 명시하고 헤딩 □ 자동추가를 끈다. official은 발송 공문용 외형이다.
자동 장평축소는 끄고 글머리 내어쓰기는 엔진 계산을 사용한다. 기존 파일 덮어쓰기를 거부한다.
현재 경로의 목록은 번호 문자열+문단 서식이다. 한글에서 항목을 삽입할 때 자동 재번호되는
네이티브 번호 목록이라고 안내하지 않는다. 원본 MD에서 수정 후 새 파일로 재생성한다.

## 제목 상자 기본형

보고서·계획서의 첫 제목은 위아래 파란 띠 + 흰색 제목 영역 + 가운데 정렬을 유지한다.
제목은 HY헤드라인M 22pt로 통일한다. 제목의 길이에 따라 크기를 자동 축소하지 않는다.
이 서체는 자체 획이 굵으므로 중복 bold를 강제하지 않는다.
글꼴이 없고 맑은 고딕 Bold가 설치된 환경에서는 helper가 그 서체로 대체하고 실제 서체를
출력한다. 기관 지정 서체는 `--heading-font`로 우선 지정한다. 글꼴 대체가 생긴 미리보기는
원래 서체의 모양을 검증한 결과라고 말하지 않는다.

근거와 성격(2026-10-15 확인):
- [국가공무원인재개발원 정책기획 실습](https://www.nhi.go.kr/upload/basicBook/04.pdf),
  인쇄 54쪽: 제목 HY헤드라인M 20~22pt, 테두리 0.3mm, 연한 옥색 바탕 예시.
  유형·분량에 따른 조정을 허용한다. 발행일 미확인. 이는 파란 띠 자체의 근거는 아니다.
- [kordoc 제작자의 공공 GitLab 실측 명세](https://gitlab.aigov.go.kr/chrisryugj/kordoc/-/blob/v4.18.8/docs/gongmunseo-engine-spec.md):
  정부 보고서 양식 표본의 제목박스 HY헤드라인M 22pt와 파랑 장식 구조를 구현한 기록.
  제작자의 실측·구현 자료이며 정부 전체의 의무 규정이 아니다.
- [법무부 2026 성과관리 시행계획](https://www.corrections.go.kr/bbs/moj/161/494287/download.do),
  2026.4.: 장·절·표 등의 실제 서식은 문서 유형별로 달라 단일 제목 외형을 전국 공통으로
  일반화하지 않는다. 이 문서를 파란 띠의 동일 치수 근거로 쓰지 않는다.

파란색과 상하 띠 각각 382 HWPUNIT≈1.35mm는 엔진 구현을 유지한다
(색 #0080C0, 하단 그라데이션). 제목 가운데 셀은 **6803 HWPUNIT≈24mm 고정**으로,
한 줄/두 줄 모두 같은 높이를 사용한다. 세로 CENTER·가로 CENTER 정렬을 유지하고,
셀 위아래 내부 여백은 각각 141 HWPUNIT≈0.5mm로 동일하게 둔다.
한 줄의 남는 공간은 세로 가운데 정렬로 분배하고 두 줄은 같은 셀 안에서 자연 줄바꿈한다.
이 높이와 여백은 사용자가 선택한 운영 설정이며 공식 표준 수치가 아니다.

helper는 새 생성물을 임시 경로에 만든 뒤 `fix_title_height.py`가 설치된 python-hwpx의
공개 `cell.set_size()` API로 제목 셀 높이만 지정한다. 저장 후 높이·제목 텍스트를 재확인한다.
별도 XML 파싱이나 설치된 패키지 수정은 하지 않는다. `hwpx-kit`과 같은 가상환경의 Python을
자동 선택하며 다른 설치 방식은 `--hwpx-python`으로 지정한다.
공개 API로 내부 여백을 새로 설정하는 대신 엔진의 기존 고정 여백/정렬을 보존한다.
제목이 두 줄을 넘는 것으로 예측되면 출력을 중단하고 제목 단축/부제 분리를 안내한다.
한글에서 나중에 제목을 늘리면 셀이 자동 확장될 수 있으므로 UI 편집까지 잠그는 기능이라고
안내하지 않는다. 1~2줄 생성 범위에서 동일 높이를 보장하는 설정이다.
SVG에서 하단 띠 그라데이션이 재현되지 않으면 한글 실물과 구분해 알린다.

## 배치 원칙과 현재 한계

같은 역할·레벨은 동일 설정, 부모–자식은 가까이, 동급 새 묶음은 넓게 배치한다.
줄간격은 문단 내부에만 사용하고 문단 사이 간격은 before/after로 관리한다.
번호 영역과 본문 시작점을 분리하고 후속 줄은 본문 시작점에 맞춘다. 긴 번호는 글머리 폭을
측정한다. 반복 공백·빈 문단·임의 개행으로 정렬하지 않는다.

실제 생성 설정은 [paragraph-spacing.json](paragraph-spacing.json) 한 곳에서 관리한다.
- 본문 문단 내부 줄간격 160%, 참고/주석 140%.
- 첫 본문 항목 앞 0pt(제목과의 기존 간격 유지), 새 대항목 앞 15pt.
- 자식 묶음이 끝난 뒤 상위 레벨의 다음 항목 앞 9pt.
- 같은 묶음의 연속 항목 또는 첫 자식 항목 앞 3pt.
- 참고/주석 앞 2pt, 모든 적용 문단 뒤 0pt(여백 중복 합산 방지).

이 수치는 사용자가 승인한 운영값이며 공식 강제 수치가 아니다. `apply_paragraph_spacing.py`가
신규 생성물에만 공개 `set_paragraph_format()` API로 적용한다. 들여쓰기/글자모양/쪽나눔은
기존 값을 상속하고, 바로 다음에 자식이 오는 부모 문단에는 keep_with_next를 설정한다.
제목표와 본문 표의 문단·셀 서식은 건드리지 않는다. 일반 서술문에는 자동 역할을 추측해
적용하지 않으며, ※/*는 참고 역할로 처리한다. 기존 사용자 문서의 정규화 도구가 아니다.
번호 없는 단독 항목은 현재 kordoc 4.9의 전용 문단 참조(25~32)로 레벨을 보완하므로
엔진 업그레이드 시 단독 항목과 8단계 회귀 사례를 다시 검증한다.
같은 중항목이라도 직전 자식 묶음 종료 여부에 따라 3pt/9pt가 달라지는 것은 의도된 경계 규칙이다.

## 검증

`hwpx-kit validate --json`와 `read --format text --json`으로 구조, 번호 순서, 텍스트 보존 확인.
형제 2개 이상, 8단계, 9→10, 부모 변경 뒤 재시작, 단독 항목, 긴 글머리, 긴 문장,
참고·주석, 표 전후, 쪽 경계 사례를 검토한다. 참조/표가 목록 중간에 있으면 번호 재시작도 점검한다.
렌더에서 둘째 줄 정렬·고아 제목·표 잘림을 확인한다. kordoc SVG는 근사이고 한글의 실제
페이지 배치 확인을 대신하지 않는다. 사용자 강조/쪽나눔/표 및 본문 상호참조는 보존한다.
DOCX 변환도 같은 기준으로 확인하되 자동 재번호와 직접서식 충돌을 별도 점검한다.
